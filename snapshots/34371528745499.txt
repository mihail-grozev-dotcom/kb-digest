Title: Dynata QualityScore Integration
This logic node allows for integration with the Dynata QualityScore API (v1.5.1). Together with speeder and straight-liner detection, the Dynata QualityScore outputs a score ranging from 0-100 for participants at the end of the survey. This API reads respondents in survey behavior and passes data to Dynata’s servers to analyze, which results in a score being passed back into your survey data.
Note: The Dynata QualityScore logic node provides QualityScore, RealAnswer, and RelevantID services. These logic nodes cannot be added to a survey that already has a Dynata QualityScore logic node to prevent redundancy.
To use the QualityScore, you must place two elements into the survey:
The QualityScore logic node, which should be the first element of the survey.
The companion element, which must be on its own page after all questions pages, and can only be added via XML
1: Adding the QualityScore Logic Node
There are two ways to add the QualityScore Logic Node: using the Survey Editor or via the XML Editor.
1.1: Using the Survey Editor
The QualityScore logic node is located under the Advanced category inside the Survey Editor.
The QualityScore logic node should be the first element in the survey, as it collects and sends data from all questions that come after it. The RelevantID call is performed where you place the logic node.
The following fields are available:
Client ID: Your unique Client ID, assigned by Dynata.
GeoCodes (Geographic Codes): A comma-separated list of country codes. This field is required to enable RelevantID.
After adding the logic node, you must add the Companion element (qualityscore_analyze) to the survey using the XML editor.
1.2: Via the XML Editor
The QualityScore logic node should be the first element in the survey, as it collects and sends data from all questions that come after it. Add the following code to the survey’s XML:
<logic label="ln1"
qualityscore:ClientID="123"
qualityscore:GeoCodes="1,US"
uses="qualityscore.3" sst="0">
<title>Dynata QualityScore</title>
</logic>
Parameter
Description
Example
ClientID
Your unique Client ID, assigned by Dynata
Required: Yes
Default: Empty
qualityscore:ClientID="A1B2-X8Y9"
GeoCodes
Comma-separated list of country codes
Required: Yes
Default: Empty
qualityscore:GeoCodes="1,US"
or
qualityscore:GeoCodes="1,US,FR,CA"
LangCodeMap
Comma-separated list of English generic languages (english_g1, … english_g10) and LanguageCode mapping.
Can be added via XML only.
Required: No
Default: Empty

qualityscore:LangCodeMap="english_g1:ES"
Mapping for 2 plus languages:
qualityscore:LangCodeMap="english_g1:ES, english_g2:TR"
After adding the logic node, you must add the Companion element (qualityscore_analyze) to the survey using the XML editor.

2: Adding Companion element via the XML Editor
The companion element is required to analyze the collected data. It must be placed in a new page by itself after all pages containing questions to be evaluated by QualityScore. Add the element using the following code to include the companion element on a new page:
<suspend/>
<html label="qualityscore_analyze" where="survey" sst="0" translateable="0">
${ln1.analyze()}
<div id="logic-node-loading-spinner"></div>
</html>
<style
label="analyze_submit"
mode="after"
name="respview.client.js"
with="qualityscore_analyze"
wrap="ready"><![CDATA[
disableContinueButton();
const analyzeSuccessful = setInterval(function() {
if (${p.client_qualityscore_results["StatusCode"]}) {
clearInterval(analyzeSuccessful);
enableContinueButton().then(() => clickContinueButton());
};
}, 500);
]]></style>
Note: The code of the above html element with the label qualityscore_analyze must be used exactly as displayed, except for the logic node’s label (ln1 in the above code). Change the companion element logic node’s label to match the QualityScore element’s logic label.
The logic node will verify that this HTML companion element exists somewhere in the survey, but you must ensure that all relevant participants see it.
You can add a suspend element after the companion element and take action based on the scores returned. The scores are captured inside a persistent variable.
3: Real Answer ClassNames
Real Answer is a solution within QualityScore. Real Answer evaluates data collected on open-end questions and indicates the likelihood of a response being genuine and made by an engaged respondent, not a bot or an AI generation tool.
To add the Real Answer attribute to open-ends, you will need to add a css classnames attribute to the open-ends via the XML editor.
You can add css attributes at 3 levels:
Question Level
Column Level
Row Level
Note: Attributes can be applied on all three levels for a single question. For example, if you have a Real Answer attribute you want to apply to all open-ends, you can add that at a question level. However, if you want to apply other attributes to individual open rows that are unique from each other, you will need to add the attributes individually per row.
3.1: Adding Real Answer attribute at the Question Level
To add the Real Answer attribute to all open-ends in a question, add the ss:questionClassNames attribute to the question. If you have four open-ends in a question, using this attribute will apply to all 4 open-ends.
Example:
<text
label="Q1a"
ss:questionClassNames="IsBrandQuestion">
<title>Text Question</title>
<comment>Please be as specific as possible.</comment>
<row label="r1">Row Label r1</row>
<row label="r2">Row Label r2</row>
</text>
3.2: Adding Real Answer attribute at the Column Level
If you have an open-end column in a question element and want to apply Real Answer attributes to that open-end, add the ss:colClassNames attribute to an open-end column.
Example:
<radio
label="Q1b">
<title>Radio Question </title>
<comment>Please be as specific as possible.</comment>
<col label="c1">Col Label c1</col>
<col label="c2" open=”1” openSize=”20” ss:colClassNames="IsBrandQuestion">Col Label c2 (Please specify)</col>
<row label="r1">Row Label r1</row>
<row label="r2">Row Label r2</row>
</radio>
3.3: Adding Real Answer attribute at the Row Level
Add Real Answer attributes by adding ss:rowClassNames to an open-end at the row level. If you have more than 1 open-end specifies in a question element and you would like to apply different attributes to them, you will need to apply the css classname individually to each row.
Example:
<text
label="Q1b">
<title>Text Question 2nd image to the right</title>
<comment>Please be as specific as possible.</comment>
<row label="r1" ss:rowClassNames="IsExcluded">Row Label r1</row>
<row label="r2" ss:rowClassNames="IsBrandQuestion">Row Label r2</row>
</text>

Use the following values for the questionClassNames, colClassNames, and rowClassNames attributes.

Data received from Dynata’s service is saved to hidden questions and is available as persistent variables at certain points while the participant is taking the survey. They are as follows:
Data Type
When Available?
How?
RelevantID results
One page after the page where the QualityScore element is placed.
Through a persistent variable: a dictionary named client_relevantid_results, where XYZ represents the logic node’s label. Keys are the field names in the RelevantID data table below.
QualityScore results
One page after the last page of the survey.
Through a persistent variable: in a dictionary named client_qualityscore_results. Keys are the field names in the QuliatyScore analysis data table below.

GeoCodes is a mandatory field specified in the configuration parameters to enable RelevantID. The standard fields returned are listed in the following table. Data is automatically captured in a hidden question on the page after the QualityScore element.

Description

Unique RelevantID used to identify the machine. A "0" value indicates an error has occurred.
Score
A confidence score which is a number between 0 – 100; 100 indicates a 100% level of confidence that the machine is dupe. A score of 75 or higher is typically considered a dupe. -1: Error.

5: Technical Details
The QualityScore logic node is a two step process:
Collect Data
Analyze Data
5.1: Collect Data
On every survey page that has a question, the participant’s browser sends the following data to Dynata when the participant presses the Submit button:
ClientID, SurveyID, RespondentID (PanelistID), PanelID
PageID: Automatically generated by the logic node as logicNodeName_questionLabels; it should be unique for each page of the survey that contains questions
Matrix Data: Values of all the matrix questions displayed on the page for the purpose of straight-liner analysis
GeoCodes: Only on the page where the RelevantID call is made
Survey Language: Indicates the language of open-ended inputs
Additional data collected by the Dynata libraries to improve analysis as well as data from all open-ended input fields for RealAnswer analysis
After the participant presses Submit, the participant’s browser will prevent the survey from continuing until the data has been sent and received from Dynata. The browser will wait for a response up to five (5) seconds.
If you would like to disable the collect data service for all questions on a page, you will need to add the following XML style overrides in the XML editor:
<style mode="after" name="survey.respview.footer" with="QUESTION-LABEL"><![CDATA[
<input type="hidden" id="qualityscore_collect_disabled">
]]></style>
The mode, name, and with attributes for the style element are required.
The value for mode must be after.
The value for name must be survey.respview.footer.
The value for with must be the label of one of the questions on the page.
Example:
<suspend/>
<style mode="after" name="survey.respview.footer" with="q3"><![CDATA[
<input type="hidden" id="qualityscore_collect_disabled">
]]></style>
<text label="q3" optional="0" size="25">
<title>New Text Question</title>
<comment>Be specific</comment>
</text>
<textarea label="q4" height="10" optional="0" width="50">
<title>New Essay Question</title>
<comment>Be specific</comment>
</textarea>
<suspend/>
5.2: Analyze Data
The participant’s browser sends the following data to Dynata when the page is displayed:
ClientID, SurveyID, RespondentID (PanelistID), PanelID
The Continue / Finish button is disabled until the data has been sent and received from Dynata. The participant’s browser will wait for a response up to five (5) seconds.
