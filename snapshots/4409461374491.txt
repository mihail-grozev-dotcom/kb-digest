Title: XML Style System
Note: The "Tear Down" guide referenced in the above video is no longer supported. For more information on individual style attributes, see the style block descriptions below.
The XML <style> tag can be used to modify or add HTML, CSS, or Javascript to create a customized survey experience.
1: The <style> Tag
An XML <style> tag can be added to a <survey> tag to apply the included styles to the entire survey, or it can be nested under a question tag to apply the styles only to that question. The <style> tag requires just a name attribute, which designates the style block to be overridden.
For example, the following code can be added within a text or number question to change the text input display style:
<style name="el.text">
… style code goes here
</style>
When adding HTML to XML styles, you can use the CDATA wrapper to avoid escaping special characters. In the <style>tag, start your content with "<![CDATA[" and end it with "]]>".
For example:
<style name='button.continue'>
<![CDATA[
<input type="submit" name="continue" id="btn_continue" class="button continue" value="@(continue) &raquo;" />
]]>
</style>
Python code can be embedded using ${python code}syntax. For example, the following code would display the value for row 5 in question 3:
${q3.r5.val}
Ordinary survey pipes and persistent variables can also be used (i.e., :[pipe], ${p.pipe} and [pipe: q3]).
Similarly, flow control can be added using the following:
\@if (ended using \@else or \@endif)
\@else
\@endif
\@for (ended using \@end)
\@end
Note: An XML style cannot call upon other styles using [some.style] or [dynamic some.style].
See Python Expressions to learn more about accessing previous question data, or System Language Resources to learn more about system language resources.

3: Labeling & Reusing Styles
An XML <style> override can be labeled using the label attribute. This declares a group of styles that share the same label rather than one specific override. A label can be applied to any style, with the same label applied to multiple styles and not necessarily in the same location. The label is optional. Using a label on an XML <style> allows the use of the copy attribute which at any other point in the survey can reference that label to copy everything in the <style>.
4: Style Variables
Style variables created through the arg:var="value" attribute are referenced in the <style> tag using $(var). Variables can be filtered; for example, $(var|upper) changes the text to uppercase.
For example:
<style name=el.text arg:before="€" mode="before">
$(before)
</style>
Why would you put the € inside the attribute rather than just putting it directly in the style override? The advantage comes when using this style multiple times while slightly adjusting the text. When defining this style within "q1" with "€" the <style> can be copied and a new value can be set for the variable before in "q2".
For example:
<style copy="q1" arg:before="AUS$"/>
There is no limit to the number of arguments for a <style>. When copying the style using <style copy=...>, supplying new values for the arguments overrides the original, and the arguments that are not supplied in the copy use the original.
5: Calling on the Default Style
Often you would want to enhance an existing style, reusing the default but just adding HTML before / after, or wrapping some HTML around the code. This can be done using [super]. Inserting [super] displays the custom styling and then display the rest of the style as if the override was not there, right where [super] is.
[super] also works within overrides. For example, a footer can be overridden multiple times and if each called [super], all the overrides would be appended after each other. The mode attribute is set to "after" or "before" to implicitly add a [super] at the beginning or end of the style.
6: Declaring Static Resources
An XML style may often refer to local static resources. Typically, those will be saved in your/survey/static/file.png and referenced as /survey/your/survey/file.png.
The shortcut [rel file.jpg] can be used to insert a link that is relative to the current survey. This automatically sends access to the file through a caching proxy server that accelerates the download of the resource.
7: Wrapping With Javascript
To run some Javascript after a certain question has been displayed, you can use the following override:
<style name="question.after" with="q0"> <![CDATA[
<script>
jQuery(document).ready(function() {
$ ("#someelement").doSomething();
});
</script>
]]></style>
Using wrap="ready" will add the script tag, wrap the code in a jQuery-ready function, and simplify the code to the following:
<style name="question.after" with="q0" wrap="ready">
<![CDATA[
$ ("#someelement").doSomething();
]]></style>
8: Applying Styles
In addition to applying styles to specific rows or columns using the rows and cols attributes, XML styles can be applied based on logic conditions and the attributes before, after, or with.
8.1: Using Cond to Apply Based on Logic Conditions
A <style> can have a condition, which is Python code just like a question condition. For styles that refer rows / cols, the row variable or any other variable passed in can also be used in the condition. Using conditions can be useful when creating a custom question style that should present a different look and feel on mobile devices.
8.2: Using Before & After to Apply During Parts of the Survey
Global style overrides may be given an after and before attribute, referencing any label in the survey (questions, <label> elements or <html> elements). Each time a survey page is displayed, Decipher tracks the first element that might be displayed on the page. This element will be used to determine which after / before styles are applied. If a <style> has after set, it will only be displayed if the after element precedes the first element on the page. If a <style> has before set, it will only be displayed if the before element succeeds the first element on the page.
Note: It does not matter whether the participant actually saw this element; what matters is the relative position (in the survey.xml) of the before / after element versus the first element to be shown on that page.
For example, consider the following three-page survey with "q1", "q2", "q3", each on its own page, and three style overrides:
Page contains
before="q2"
after="q1"
after="q1" before="q3"
q1
X
q2
X
X
q3
X
The "X" above denotes on what pages each style override will be effective.
The before="q2" style override is displayed only on the page containing "q1". As soon as the "q2" element becomes the first element on the page, it is no longer shown. Thus it can be used to apply a special style in some introductory section of the survey.
The after="q1" style override only takes effect when an element after "q1" in the survey.xml is displayed as the first element on the page.
Note: When displaying any exit page, Decipher uses the first question on the page as the very last question in the survey regardless of what was displayed to the participant.
8.3: Using With to Apply Based on Question Visibility
It is also possible to override a global style when a question is being shown to participants using the with attribute. The with attribute specifies a comma-separated list of question labels, each of which must have just been displayed for the style override to take effect. The questions must have actually been displayed (not just skipped due to conditions).
9: XML Style Blocks
A page style applies to the entire survey page and can be nested anywhere in the <survey> tag, but not within a <block> or question tag. These style overrides allow the use of the attributes after, before, and with, but not rows or cols. A question style applies only to the question it is defined in. It cannot be defined anywhere else. However, you can copy styles in questions and define a style block outside of any questions.
